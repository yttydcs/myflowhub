## 经验 / 教训摘要

- “当前工作树能跑”不能替代 clean checkout；未跟踪构建输入和 checkout filter 只有在新 clone 中才会暴露。
- Windows `core.autocrlf=true` 会让 `gofmt -l` 把整个仓库判为未格式化，必须由 repository attributes 定义 Go 源 EOL。
- tracked Wails/Vite 产物需要与 generator 的 byte contract 一致；相同文本也可能因混合 EOL 或最后换行产生 drift。
- Gradle 在 Windows 上同时依赖短 TEMP 和兼容 JDK；`AllowUnavailable` 只允许缺工具显式跳过，不能掩盖真实失败。

## 可复用排查线索

- 症状：fresh clone 的 `gofmt -l` 列出几乎所有 Go 文件。
- 触发：Windows `core.autocrlf=true` 且 `*.go` 没有 `eol=lf` attribute。
- 症状：Wails/Vite/build 成功，但 `git status` 出现 `dist/`、`wailsjs/` 或 `package.json.md5`。
- 关键词：`i/lf w/crlf`、`No newline at end of file`、`generated source differs`。
- 快速检查：`git ls-files --eol -- <path>`、`git diff --ignore-space-at-eol`、在 fresh worktree 执行 generator 后 `git diff --exit-code`。
- Gradle 关键词：`Unable to establish loopback connection`、`JavaVersion.parse`、`25.0.4.1`；快速检查 `MFH_SHORT_TEMP` 和 `MFH_JAVA_HOME`。

## 关键设计决策与权衡

- 只为 Go 和两套 tracked frontend generated trees固定 LF，不做全仓格式化，控制 diff 与兼容风险。
- 保留历史 workflow 文档作为 plan/change/lessons，不让它们取代当前 features/requirements/specs/decisions 真相。
- 排除论文、附件和 dirty `guide.md`；历史凭据只保留“曾嵌入”的诊断事实，具体值脱敏。
- 不修改全局 Java/TEMP；通过脚本已定义的 per-process 环境变量完成验证。
