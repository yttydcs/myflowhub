- 本轮范围固定为：
  - `MyFlowHub-SubProto`
  - `MyFlowHub-MetricsNode`

目标：
- 在不引入计划外功能改动的前提下，完成依赖升级、验证、Code Review 与归档。
- 为后续发布动作准备好可直接 merge / push / tag 的提交状态。

## 关键设计决策与权衡
- 维持既有发布策略，不在本轮顺手重构版本体系：
  - `SubProto` 继续按 module 分 tag
  - `MetricsNode` 继续使用 `main` + `debug-latest`
  - `Win` 继续单仓 semver tag
- 接受 Go 最低版本提升：
  - `Core v0.4.0` 已要求 `go >= 1.25.0`
  - 不做人为降级兼容，避免后续在工具链层面继续分叉
- 对 Wails 仓库继续采用“验证时创建临时 `frontend/dist/.keep`”策略：
  - 满足 `go:embed all:frontend/dist` 的编译前置
  - 不把构建产物目录纳入版本库，保持仓库整洁和可维护性
- 兼容修复坚持“最小必要”原则：
  - 本轮实际未出现需要落地的 API 适配代码，说明当前版本升级风险受控

## 潜在影响与回滚方案
### 潜在影响
- 下游最低 Core 依赖统一提升到 `v0.4.0`。
- `SubProto` 和 `Win` 的最低 Go 版本提升到 `1.25.0`。
- Wails 项目在本地直接执行 `go test` / `go build` 前，仍需保证 `frontend/dist` 至少存在一个文件，或执行既有前端构建流程。

- 已发布后：

  - `MetricsNode` 若 `main` 已推进，优先追加修复提交，而不是强行重写历史。
