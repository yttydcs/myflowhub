# Flow 移除与重新设计延期

## User Request

> 那能不能先移除掉flow，然后把flow设置为待办，减少现在代码演进的负担？

此前讨论明确：目标是通用协作平台，文件、剪贴板、全局通知只是其中的应用。
网络模型只认识节点、网络和资源；设备与插件不是这个模型的对象。
节点独立提供能力，同一设备可以运行多个节点，节点内部可以自行实现插件机制。

用户认为早期 Flow 模型可能过时，提出讨论内部语言以获得更自由、适合 AI 编写的自动化表达。
用户要求切换方案前给出现有方案与候选方案对比，不直接开始替代实现。

## Accepted Scope

本次明确授权移除现有 Flow 并记录待办。包括实现、Hub 装配、专属公开契约、SDK、界面入口、
生成产物和直接依赖；同步当前文档。保留通用资源基础能力、历史资料及已有运行数据。
本次没有选择或授权实现新的执行器、内部语言或网络模型。
