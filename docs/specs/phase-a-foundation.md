# A 阶段目录、容量与恢复技术合同

状态：实现中；目录、容量、批量桥及本机故障路径已实现，正式双机验收仍待验证。进展与证据见根级 [review](../../review.md)。产品门槛以 [A-AC-v1](../requirements/phase-a-acceptance.md) 为准，不在此调整。

## 目录分页

保留 `system/catalog`、`mfh.variable` v2、标准 read/subscribe。新增 `list` capability，permission 为 `resource.catalog.list`；schema 分别为 `mfh.catalog-list.v1` / `mfh.catalog-page.v1`。旧小目录仍提供完整 `mfh.catalog.v2` 值；大目录通过标准 unavailable 状态说明必须分页，绝不静默截断或让旧快照编码失败阻止新注册。订阅该目录仍可观察成员变更及代际；目录修订只随成员变更推进。

请求 `{version:1, limit?:128, cursor?:string}`；limit 1—256，省略/0 使用128。游标是有界不透明字符串，包含目录 instance_id、成员 revision 与 next offset，并绑定 owner；服务端严格解码和校验，跨 owner/实例/成员修订明确 conflict，非法游标 malformed。分页不是访问授权凭据，每次调用仍执行既有 capability 授权。

响应 `{version:1, owner, instance_id, revision, offset, total, resources, next_cursor?}`，其中 revision 为规范十进制 uint64 字符串，owner 保持普通 wire NodeID 数值编码。resources 严格按名称排序、owner 一致，total 1—4096（含 catalog），每页最多256条；单页编码不超过512KiB，单条不能装入则 overflow。offset/总数/下一游标一致，非末页必须前进；编码必须通过标准严格 JSON DTO 校验，不扩大1MiB全局消息上限。

SDK `Catalog` 保留已有单次read bootstrap；仅owner明确返回overflow unavailable时进入分页，仍须独立list授权。显式 `CatalogPages` 可供只有list权限的消费者使用；分页只在明确unsupported时回退旧完整read，forbidden/timeout/malformed/overflow不回退。聚合各页要求owner/instance/revision/total一致、offset连续、无重复/乱序，最多4096条；拿齐后再发布完整列表。成员变更conflict最多重新开始两次，仍冲突明确返回；不拼接不同代际，取消立即结束。

Registry 批量注册在单次锁定中校验所有资源、owner/重复/保留名称/retired/4096总量；失败原子回滚且不发布部分目录。完整legacy值无法装入时发布无值 unavailable（错误码 overflow），恢复到预算内后再次提供完整ready值。目录分页读取从同一锁保护的已排序成员快照生成，避免每一页重复扫描/排序全表；成员事务一次刷新快照。

## 容量、批量桥与恢复预算

帧编码把固定头、各元数据段和载荷合并为同一次底层写入；仍使用原字节布局，短写继续补齐。多段TCP写入在Windows的2000@1Hz参考流量下已触发有界发送队列溢出，因此不能仅靠扩大队列掩盖吞吐问题；合并不改变协议主版本、载荷硬界或队列预算。

A产品运行时及Desktop业务订阅预算起始4096，管理订阅另核计数；队列有界且缺口明确，生成物从统一工具生成。批量poll最多256事件/256KiB软预算，空闲等待≤100ms，Desktop桥使用16ms最短合批间隔，超软预算单条按协议硬界独立处理；公平轮转、owner client固定、2000续租分散，UI虚拟行不改变订阅寿命。原生Windows验证发现起始64事件批次积压，按同一字节预算调大事件上限；512事件诊断轮仍积压，未采用。不缩减活动订阅或丢弃数据来提速。

原生Wails调用`PollSubscriptionsBatch`直接取得结构化数组，保留`PollSubscriptionsJSON`及单订阅接口兼容既有调用者。SDK严格校验网络载荷，Desktop将受限批次的RawMessage交给Wails统一编码；不再把整批JSON作为字符串再次包装并由前端重复解析。前端继续检查批次形状、数量、请求句柄、重复项、事件种类及字段，并逐条执行变量合同校验。该路径的实际吞吐和时限证据以review.md为准。

SDK订阅解码器缓存已验证的类型化definition；无definition的后续事件使用深拷贝恢复定义，避免每次重新解析相同schema。返回值与缓存的指针、切片及嵌套schema全部隔离；仍逐事件校验资源、实例、修订、状态值和完整载荷上限，gap/expired清空缓存，同一实例不得更换definition。绑定层保留对外部流的独立校验，不以吞吐优化绕过信任边界。

产品配置 heartbeat1秒/idle3秒，reconnect100ms起最大1秒，并发启动32。链路控制/数据/入站队列各4096帧，同时分别限制8/32/32MiB；控制与数据预算独立，写出中或等待交付的帧仍计字节占用。满队列明确失败，不无限扩容。SDK 续租分散在租期65%—79%，暂时路由失败仅对订阅建立做100ms至1秒退避，不重试写操作。

所有5秒写入终态均保留结果不确定语义，不自动重试/补发。收到可靠写确认后另行读取；读取失败显示“写入已确认，回读失败”。超时后的旧回包不得发起回读或覆盖状态。正常2秒确认、5秒断网识别、10秒网络恢复、15秒进程恢复和3秒撤权仍分别验收，本机结果不替代真实设备证明。

可读取的变量在用户明确提交时先读取一次当前状态；只有实例和原业务值仍相同、且没有草稿冲突/失效时，才使用最新有效修订执行一次条件写入。写前读取、单次写入及写后回读共用原5秒截止，不自动重试写入；实际值变化保留草稿并明确冲突。Windows退出确认使用原生Yes/No返回值，默认No保留更改，提示文字明确询问是否放弃并退出。

原生`WriteVariableFromSnapshot`在单次Wails调用中完成预读、实例/定义/基值比较和唯一一次CAS，减少两个IPC往返之间的修订老化。返回值区分预读阶段与已经发送写入的阶段，客户端据此表达拒绝或结果不确定；写确认后仍由前端独立回读。旧写接口保留，不支持该入口或JSON无法保留负零基值时继续使用原路径，不自动重试冲突写入。

子连接就绪确认和父节点路由可见性在同一会话注册临界区内发布；确认入队后，父节点路由读取需等待会话安装完成，避免子节点收到join确认立即请求时遇到不存在的next hop。该临界区只执行有界入队，不等待网络I/O。

权限变化只终止实际失去订阅授权的兴趣；仅撤 write 不误杀 read/subscribe。权威转发逐次校验有效授权，断开的 owner 路由立即使远端兴趣失效，消费者不必等待自身父连接变化或租期结束。SDK 在中断时立即发布 gap，取得完整新快照后才能恢复实时状态。

续租正常替换句柄不制造缺口；若旧句柄已退休而下一轮等待父连接或建立订阅瞬态失败，则立即失效最近值，在新值到达前只发一次对应gap。连接等待循环内执行状态检查和失效，避免单独预检查与实际等待之间的竞态。界面将实时数据与写入异常分别显示，拒写不代表仍授权的订阅已经失效。

总览所持订阅同时保留资源描述，与连接变化时重置的发现目录独立；目录暂时清空不能让仍被观察的行消失。当前目录描述优先更新标签，值与有效性继续来自共享变量控制器；撤权/断连不会因保留描述而变成实时。明确停止订阅或切换Profile释放该集合，选择仍为会话状态，不新增旧版状态文件字段。

## 测量与证据

Metrics Windows 图形版成功启动节点后保存公开连接参数及 active 意图，关闭窗口保留该意图，明确点击“停止节点”则保存 inactive。启动时只恢复 active 配置，身份文件缺失不重新生成身份；损坏配置和恢复失败显示原因。一次性 Permit 不写入 GUI 配置。GUI 配置默认为 `%APPDATA%/MyFlowHub/metrics/connection.json`，隔离部署可用绝对路径 `MFH_METRICS_CONFIG_DIR`；实际身份和采集策略仍在用户选定的产品状态目录。连接参数/采集策略草稿参与原生退出确认，默认取消，保存策略不会清除其他连接草稿的未保存状态。该文件独立于旧版可读取的 Metrics 状态；旧图形版不具备新增的自动恢复行为。

统一观察者单调时钟关联submit/UI/owner/Windows独立回读，跨机校准误差记录；故障起点来自注入生效记录，网络恢复起点来自双向可达探测，启动起点包含初始化。private committed bytes按产品与专属子进程归属记录，不能用工作集代替或重复计数共享子进程。原始证据带候选commit/hash、环境、参数与逐次判定；缺真实机器/音频端点记Unavailable，全部必验项通过才完成A。
