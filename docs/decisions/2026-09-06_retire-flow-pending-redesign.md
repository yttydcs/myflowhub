# Retire Flow Pending Redesign

## Status

Accepted，依据用户明确提出“先移除 Flow，设置为待办”。
取代旧 Flow 规格中关于当前交付能力的描述；通用 Collection/Capability 决策继续有效。

## Context And Options

平台正在重新明确节点、网络和资源的边界。早期 Flow 的定义与执行方式尚未被确认为未来模型。

| 方案 | 收益 | 代价 |
| --- | --- | --- |
| 继续保留旧 Flow | 已有执行场景继续可用 | 核心演进需要继续维护旧契约、生成产物、客户端与测试 |
| 移除并延期重新设计（采用） | 当前实现和交付范围缩小；后续重新讨论不受旧执行模型绑定 | 当前版本暂时没有内置 Flow 自动化，旧客户端的 Flow 调用失效 |
| 立即重写或引入内部语言 | 可以探索新的表达能力 | 模型与语义尚未确认，超出本次授权 |

## Decision And Consequences

移除当前 Flow provider 和专属契约、SDK 与产品入口，保留节点、网络、资源、通用调用/订阅、Collection 和授权机制。
不引入替代语言、兼容执行器或新的网络对象。实现方式中的插件不成为网络概念。

持久化的 `flow.json` 原样保留，新程序不再加载或执行其中定义，也不新建 Flow 状态。
旧 Flow schema、Go 类型和 FlowClient 从当前公开表面移除，这是本次明确接受的兼容性变化。
既有授权状态不被清理；未来实现必须另行决定授权迁移，不能仅凭复用旧资源名启用旧授权。

代码历史和带历史标记的规格用于回顾，不作为当前 API 或继续维护旧 Flow 的要求。
恢复自动化工作前，先完成[重新设计待办](../requirements/flow-redesign.md)中的方案对比与讨论。
