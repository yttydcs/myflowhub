# Flow Redesign

## Status

旧实现已移除，新实现待设计。2026-09-06 起的产品讨论已明确核心模型与默认运行原则，结论于 2026-10-09 汇总至[统一产品定义](product-definition.md)第 5 节，并于 2026-10-19 同步至主线工作区。具体语言引擎、技术合同及验收范围仍未选定，未进入实现阶段。

本文件保留退役边界和后续设计入口；已确认的 Flow 产品规则集中维护在统一产品定义，逐项来源见[讨论 P04—P19](../intake/2026-09-06_product-definition-grill.md)。

## Product Intent

目标是通用的节点协作平台，让节点提供的能力能被发现、组合和自动化调用。
剪贴板、文件和通知协作只是应用场景，不限定平台的能力范围。

网络模型只认识节点、网络和资源。节点是提供或使用能力的参与者，不等同于物理设备。
同一设备可以承载多个节点，例如提供邮件通讯资源的节点；部署位置不成为网络模型的对象。
网络模型没有插件概念；某个节点可以在内部通过插件实现能力。

## Current Removal Boundary

- 移除早期 Flow 执行器、Hub 装配、内置资源与 schema、Go SDK FlowClient、Android Flow 示例入口及其专属测试/fixture。
- 保留通用资源、Collection、调用、订阅、授权与网络机制，以及文件和通知能力。
- 不读取、执行、迁移或删除已有 `flow.json`；新启动的 Hub 不再创建该文件。
- 旧 Flow 调用不再可用；不提供兼容执行器或自动重定向。未来实现不能凭旧资源名自动继承旧授权。
- 历史实现可从 Git 找回，旧规格保留为历史材料；不会继续作为当前交付门禁。

## Deferred Questions

- [ ] 在已确认的独立 Flow Resource 与节点承载模型下，设计管理、调用、观察和取消操作。
- [ ] 细化触发配置、初始快照、重复事件、断线缺口和条件组合；默认串行与有限排队已确认，队列配置及持久化待定。
- [ ] 在文本程序、优先成熟语言和节点进程内嵌入方向下选择具体引擎，验证表达、异步、调试和维护成本。
- [ ] 执行使用承载节点身份，不再讨论逐 Flow 资源/操作限权；继续定义入口授权、业务校验、有界运行与取消。
- [ ] 在显式持久状态、默认恢复、不确定则暂停及版本绑定原则下，明确保存时机、安全续行、重试、状态迁移和回滚细节。
- [ ] 选择最小但有代表性的跨节点自动化场景，制定验收标准。
- [ ] 在保留旧文件且不自动继承旧授权的边界内，决定是否需要显式导入工具；未批准迁移或恢复旧模型。

已确认规则不再按“全部尚未决定”重开；具体语言、持久化格式和 wire 尚未冻结。历史图模型与 Collections 不能直接作为新模型合同，通用 Collection/capability 能力继续有效。
