## 已批准方案与模块边界

### 有界目录发现

沿用现有 catalog 资源身份，增加可识别的分页 `list` capability，不引入新网络对象。每页同时受条目数及字节预算限制，建议默认 128 条、最大 256 条、编码目标不超过 512 KiB，仍遵守 1 MiB 单消息硬界；单条超预算明确 overflow。游标绑定 owner、目录实例、成员修订和位置；成员变更才推进目录修订，变量采样不令整本目录持续失效。

SDK 仅在拿到同一目录代际的完整页面后发布完整列表；代际变化丢弃本次不完整集合，有限重启（最多两次），仍不稳定就明确报错，不能混合新旧页。分页授权独立按现有 capability 规则检查，不因拥有旧 read 自动授予新动作；示例部署清楚授予需要的 catalog 能力。实施回归证据补充：`TestVariableCatalogBootstrapAndReadNeedsNoSubscribe` 明确已有单次read bootstrap合同，因此普通Catalog保留原read路径，只在owner返回明确overflow unavailable后请求分页；新增CatalogPages供显式分页/list-only消费者使用。分页未知能力只在明确unsupported时尝试旧版全量read，forbidden、非法载荷、超时不回退。此细化保留兼容和原权限边界，不改A验收标准。

尺寸允许时保留旧 catalog read/subscribe 的完整标准 Variable 快照；超出预算时返回明确 overflow/不可用，不能截断且谎称完整，也不让 legacy 快照编码失败阻止新版注册。通过局部批量注册事务一次校验/发布成员集，避免逐条完整序列化造成启动成本平方增长。A01 细化 schema、游标校验、旧接口超预算终态与权限测试，A02 连同稳定规格一起实现；协议主版本和全局载荷预算保持。

### 2000 真实订阅与可操作总览

Desktop 新增虚拟化资源总览：通用名称/owner/类型/真实值/有效性/权限，选中后复用标准变量编辑与明确提交。总览不把 2000 资源强行存成 2000 个手工 View 控件；现有 v3 View 与 64 控件边界保留，切换现有模式不丢草稿/焦点。总览选择状态先作为会话状态；不增加旧版严格解码会拒绝的持久字段。

总览订阅集合由工作区数据层持有，与 DOM 挂载/可见行解耦；验收选择完整的 2000 资源集合，滚出屏幕仍保持真实订阅和最新状态。总览与 View 共用同资源控制器，避免重复订阅和独立写入意图串扰；切换 Profile/断开销毁正确 client 的集合。开放页面/编辑器能看到实时值，虚拟化不得依赖关掉不可见订阅减负。

A 产品起始容量配置为最多 4096 个活动业务订阅/消费者（覆盖 2000 及目录/管理余量），桥接同量级；对外可配置且校验有效范围。Hub 的兴趣聚合/转发、owner 与 SDK 计数分别核实，不机械套用一个计数口径。全局默认不直接改为无上限；队列维持有界，满时明确 gap/overflow 并按现有规则重新取快照。批量创建/恢复起始并发 32，按公平调度和计时数据调整，不能因串行 2000 次握手错过 10/15 秒门槛。

SDK/desktop bindings 增量增加批量 poll，Wails/TS 同步生成；起始单批最多 64 事件，原生验证积压后调至 256 事件；字节预算仍为256 KiB、单次空闲等待不超过 100 ms，已有事件即返回，积压时连续排空，不以固定 100 ms 节流将吞吐限制在 640 事件/秒；按订阅轮转避免热变量饥饿。旧 poll 保留；订阅句柄绑定原 client/session，不因切换 Profile 误读别人的 ID。缓存接收并校验全部实际事件，UI 可以每动画帧合并渲染通知；不静默吞掉协议缺口、终态或实例变化。单条合法大事件不能因批量软预算无限饿死，需独立有界返回或显式错误；1 MiB 硬界仍在。订阅续租分散调度，避免 2000 个租约同步突发超过 pending/控制队列预算；不能靠缩短实际订阅集合解决续租压力。

### 写入、权限与恢复

每次提交绑定 controller、实例、有效修订、草稿代次和会话；维持 expected_instance_id/revision 原子条件写入，不能用后续同值事件推断原请求成功。明确拒绝、结果不确定、已成功但回读失败分开。提交起 5 秒必须停止等待；网络可能已发送就标不确定，保留草稿且不自动重试/重放。正常 2 秒确认/回读门槛独立计时，不被 5 秒兜底替代；迟到结果不能盖掉新会话或新提交意图。

authority 提交的有效权限是边界：先在执行端拒绝新访问，再收束现有订阅/界面，3 秒不是服务端宽限期。撤 write 不误杀仍授权 read/sub；撤 read/sub 后不得再送确认点后生成的保护值。撤权与已经授权执行中的写分开记录；重新授权只恢复读取，旧草稿由用户明确再次提交。

通过 nodehost 产品配置统一心跳、静默检测、重连与就绪预算。起始候选 heartbeat=1 秒、idle=3 秒（现 sweeper 约 idle/2，因此检测预算约 4.5 秒，尚须全链路/UI验证）；重连 100 ms 起、倍增、最大 1 秒，并发启动有界。A 产品应用并校验该配置，不能只改 Desktop；在持续负载下确认数据队列不会饿死心跳/控制包，长中断不忙循环。值不满足时改调度/检测实现，不能以参数估算当作已通过。

网络实际双向可达后 10 秒内恢复最新快照/订阅；进程启动起 15 秒包含初始化。恢复按现有连接 generation 清理，只允许当前 parent/session 结果落地；不把最新状态恢复宣称全部事件回放。saved active Profile 自动接回；主动退出/选择 Profile 意图保留；不造新身份绕过错误。Hub/Metrics 重启不丢仍运行 Desktop 的草稿，Desktop 进程死亡只要求已提交保存状态；正常退出检查草稿和未保存布局，允许取消。
